# 05：静态资源盘点与用户交接边界

## 文档状态

- 状态：前端云路径接入已于 2026-09-24 回退；本阶段仅保留资源盘点和后续验收要求。
- 用户负责图片、图标、字体、媒体和插画的目录调整、云端上传、URL 配置与实际替换。
- 前端不得预先移动仍在使用的资源，不得建立 `VITE_STATIC_ASSET_BASE_URL` 或 `src/static-assets` 切换层。
- 资产清单是盘点证据，不代表授权迁移、删除或接入云路径。

## 阶段目标

1. 记录可能影响首屏的本地大资源及其引用场景。
2. 明确用户手工处理静态资源、前端只在新路径确定后调整引用的责任边界。
3. 保留与路径迁移无关的性能优化，例如图片固定尺寸、唯一 LCP 高优先级和 Dashboard 字体按需注册。
4. 为用户完成迁移后的构建、网络、CORS、Canvas 和页面验收提供清单。

## 当前实现结论

- ABI、Chat、Dashboard 运行时代码与配置中不再保留本轮预置的云静态资源解析层。
- ABI 原有 12 个 SVG 已恢复到 `apps/abi/src/assets/svg-icon/`，没有 `svg-illustration` 运行时引用。
- ABI 本地图标继续按需加载；没有恢复全量 SVG Sprite 首屏注册。
- ABI 登录背景和插画保留固定尺寸及加载优先级；Dashboard 字体继续按项目数据注册并使用 `display: swap`。
- 当前没有删除或移动用户负责处理的图片、图标、字体和媒体文件。

## 后续协作流程

1. 用户手工完成资源上传、目录调整或文件替换，并提供明确的新路径或 URL。
2. 新建独立需求，列出允许修改的引用和允许删除的旧文件。
3. 前端只调整已明确的引用，不顺带迁移其他资源。
4. 需要删除图标时，先完成引用扫描、生产构建和页面回归；三项均证明未使用后才能删除。
5. 云资源逐项验证 200/304、Content-Type、缓存、尺寸占位和错误态。
6. 字体及参与截图/导出的图片额外验证 CORS、FontFace fallback 和 Canvas 不被污染。
7. 完成后重新执行首屏预算门禁与关键页面桌面回归。
